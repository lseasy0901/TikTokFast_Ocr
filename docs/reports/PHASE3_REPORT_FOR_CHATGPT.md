### 2.2 关键设计点

- **挂载点是互斥的**：`if best is None and self._length_escalation and self._has_length_anomaly(seen)`。
  既有的 case-fold 复看要求 `best is not None`，本档只在 `best is None` 时生效，
  因此**同一帧不会连做两次复看**。
- **触发只认「偏长」**：`_has_length_anomaly` 用 `len(text) > max(格式长度)`。
  9 位对 8 位格式触发；标题卡那种 3~7 位偏短读法**不触发**
  （这也是把初版「长度不等于任何格式」改掉的原因——初版会在 11 帧标题卡上白跑复看）。
- **复看结果不特殊对待**：`_escalate_length` 只做「放大 + 再走一次 `_decide`」，
  返回的候选由 `recognize_frame` 统一交给 `self._resolver.offer()`，
  与正常路径走**同一条**严格校验与 `TemporalResolver`，不直接输出、不触发复制。
- **不做字符级操作**：没有删除、没有替换、没有字形切分、没有白名单、没有新依赖。
- **关闭时零影响**：`self._length_escalation` 为 False 时 Python 短路，
  `_has_length_anomaly` 不会被调用，热路径只多一次布尔比较。

### 3.2 失败根因（本阶段最重要的发现）

`QAZW4602` 第 308 帧：

```
1.0x 读法          : QOAZW4602（9 位）
生产复看（dsize）  : OAZW4602   <-- 错误但合法，被采纳
探针复看（fx/fy）  : QAZW4602   <-- 正确
真值               : QAZW4602
```

三个事实叠加：

1. **9 位读法本身带二义性**。`QOAZW4602` 有两种同样合理的解释：
   删掉中间的 `O` → `QAZW4602`（真值）；**掐掉开头的 `Q`（偏移 1）→ `OAZW4602`**。
   第二种正是 `ocr/room_code.py` 里 `_MIN_WINDOW_RESIDUE` 注释明确拒绝的
   「偏移 1 滑窗」——那次拒绝的理由就是它会产出**零纠正的错误码**。
   复看只是换了个倍率，并不天然知道该选哪个解释。

2. **两种 `cv2.resize` 写法产生的像素不同**。目标尺寸都是 1000×339，但：
   - `cv2.resize(img, None, fx=1.5, fy=1.5)`（Phase 2 探针用）
   - `cv2.resize(img, (1000, 339))`（现有 `_escalate` 用，也是本次实现照抄的写法）
   两者**有 73,673 个像素不同**，因为 fx/fy 路径的内部缩放因子是 1000/667 = 1.49925 而非 1.5。
   这点差异足以让 Tesseract 落到另一个解释上。
   **也就是说：实验阶段的收益有一半来自这个采样网格的巧合，而不是机制本身。**

3. **注入错码会打断时序确认**。第 308 帧从「无结果」变成「错误但合法的 OAZW4602」后，
   `TemporalResolver(2/3)` 在 QAZW4602 的显示窗口里看到的序列是
   `[QAZW4602, OAZW4602, QAZW4602, OAZW4602]`，任何一侧都凑不齐连续 2 次一致
   → 该码**永远不会成立** → 原本正确的码变成漏。

> 注意：**帧级「新增错误」指标为 0，掩盖了这个回归**。
> 因为第 308 帧在 OFF 时是「无候选」、在 ON 时是「错误候选」，两者按帧级口径都不算「正确」。
> 只有**码级**指标才暴露出来。第一版回归脚本用的正是帧级指标，是被这一步补上的。

## 5. 残余风险

1. **9 位读法的二义性没有解决**，只是被「碰巧落到哪个采样网格」掩盖。
   换一个倍率、换一版 OpenCV、换一台机器的插值实现，都可能翻转。
2. **无留出样本**。全部 100 个码都参与了设计与验证，任何「100/100」都不构成泛化证据。
3. **收益边界窄**。本机制只能救「9 位插入型」这一类；类 I（`HJKT6402`、`QRTP8641`）
   完全不触发，仍是未解决的错误。
4. **`_ESCALATION_SCALE`（2.0，case-fold）与 `_LENGTH_ESCALATION_SCALE`（1.5）
   是两套倍率**，语义不同但容易混淆，后续维护需注意。

## 6. 是否具备进入第五轮实测的条件

**不具备。**

理由：本阶段的验收条件是「完整 373 帧回归中没有新增错误、且确实有净收益」。
生产实现（`ocr/room_code.py` 的 dsize 缩放路径）在完整回归中出现了
**1 个码级回归**（`QAZW4602` 正确 → 漏），尽管码级正确数从 95 升到 97。

按你的指令「如果任何验收条件不满足，不要启用新功能」：

- **代码保留但开关默认关闭**（`length_escalation=False`），生产行为与改动前逐字一致（384/384 已验证）；
- **在第五轮实测中不要打开这个开关**；
- 除非先补上「留出样本验证」，否则不建议进入实测。

### 若要推进，下一步该做什么（建议，不在本阶段实施）

1. **先解决二义性再谈收益**。护栏变体在现有数据上给出 98/2/0 且零回归，
   但它是 n=1 的证据。需要一批**专门针对偏移滑窗的样本**
   （9 位读法里「掐头」与「去中间」都成立的那些）来验证护栏的误伤率。
2. **采集时的目标是让机制失败，而不是让它成功**：重点收集 9 位插入型误读中
   「多读的字符落在开头/结尾」的帧——这正是当前唯一暴露出的危险类别。
3. 在这些数据到手并复现之前，**不建议**把 1.5x 复看接入正式链路。
