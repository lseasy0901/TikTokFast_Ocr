# TOOLBAR_SPEC — 顶部工具栏规格

> **阶段**：Phase 1（设计）/ 实施于 Phase 4
> **视觉规范**：`design-system/livelens/pages/toolbar.md`
> **按钮清单与信号槽映射**：`docs/ui-redesign/TOOLBAR_AUDIT.md`（Phase 2 产出）
> **证据标签**：FACT / INFERENCE / UNKNOWN

---

## 1. 问题陈述（任务书目标 C）

现状问题：**按钮过多、布局杂乱、图标风格不统一、设置按钮图标难以识别。**

**修复目标**：通过**分组、图标统一、优先级调整、玻璃化**使工具栏简洁清晰。

**硬约束**：**不得通过删除功能来减少按钮数量。**

---

## 2. 设计策略

### 2.1 三区分组

| 分区 | 性质 | 可见性 | 设计理由 |
|---|---|---|---|
| ① 直播控制 | 高频，直接操作直播状态 | 始终可见 | 用户最常做的动作，必须一步可达 |
| ② 业务操作 | 中频，依赖连接/游戏状态 | 始终可见（图标+中文标签） | 需要可发现性；带标签降低认知负担 |
| ③ 设置与辅助 | 低频 | 设置/许可为图标按钮；其余进 `⋮` 溢出菜单 | 低频操作不占据宝贵横向空间 |

**"简洁"的实现路径是"分层收纳"，不是"删按钮"。**

### 2.2 减少视觉杂乱的具体手段

| 手段 | 说明 |
|---|---|
| 统一尺寸 | 全部按钮 32px 高；图标按钮 32×32；图标 20×20 |
| 统一间距 | 分区内 8px；分区间 16px + 1px 分隔线 |
| 统一圆角 | 6px |
| 统一图标家族 | 单一 Outline 家族，1.5px 线宽 |
| 去边框 | 默认态透明填充 + 透明描边，仅悬停/焦点时出现 |
| 降低色彩噪音 | 仅"当前激活/选中"用 `--ll-accent`；其余用中性文字色 |
| 分组容器 | 每区一个 L2 玻璃面板，视觉上自然成组 |

### 2.3 设置按钮修复（任务书明确要求）

| 项 | 要求 |
|---|---|
| 图标 | 标准 **`gear`（齿轮）** —— 语义明确、业界通用 |
| 来源 | Skill `--domain icons` 实测返回 `gear`（Phosphor, Outline），语义 = settings |
| 禁止 | ❌ 含义模糊的自绘图标；❌ 视觉突兀的图形 |
| 工具提示 | `设置` |
| 可访问名 | `setAccessibleName("设置")` |

> **UNKNOWN**：项目现有图标资源能否提供一致的齿轮图标。若现有资源中已有齿轮图标，**优先复用**；若没有，则在**不安装新依赖**的前提下，用 Qt 内置绘制能力（`QPainter` 路径）或项目已有的 SVG 资源实现一个标准齿轮轮廓。→ Phase 2 审计后定稿。

## 3. 功能保全要求（回归基线）

> 完整清单在 Phase 2 的 `TOOLBAR_AUDIT.md`。本节定义**保全规则**。

对每一个既有按钮，改造后必须满足：

| # | 要求 |
|---|---|
| R1 | 信号槽**连接目标不变**（函数名与语义一致） |
| R2 | 快捷键**不变** |
| R3 | 启用/禁用**条件不变**（依赖的状态不变） |
| R4 | 点击后**行为不变** |
| R5 | 功能**入口存在**（要么在工具栏，要么在溢出菜单，**不得消失**） |
| R6 | 若按钮有文字标签，标签语义不变（可调整措辞但不得改变含义） |

**回归方式**：Phase 4 必须逐个按钮对照 `TOOLBAR_AUDIT.md` 清单核对，并**实际启动程序点击验证**。

## 4. 溢出菜单 —— ⛔ 已否决（Phase 4 修订）

> **本节的"低频项收进 ⋮ 菜单"方案在 Phase 4 实施时被否决。**
> 完整理由与证据见 `PHASE4_TOOLBAR.md` §3。

**否决理由（FACT）**：现有测试把「帮助 / 授权 / 设置 / 全屏入口落在标题栏操作区」
当作事实断言（`test_first_run_onboarding.py:438,442,446`、
`test_phase_ui3_1_layout.py:123-137`、`test_phase_ui3_activation_settings.py:298,309`）。
把 `_help_btn` 改为 `QAction` 会让 **287 项当前通过的断言失败**。

**替代方案（已实施）**：改为**分组 + 分隔线**降低视觉杂乱，功能入口一个不动。

```
改造前：  ?  🔑  💬  ⚙  ⛶   ‖  — □ ✕
改造后：  🔑  ⚙  ⛶  │  ?  💬   ‖  — □ ✕
          └── 功能组 ──┘   └ 帮助组 ┘
```

**可发现性保障**：5 个入口全部仍在标题栏可见位置；tooltip 与可访问名齐全；键盘 Tab 可达。

## 4b. 原收纳判据（保留备查，本任务未使用）

一个按钮适合收纳进菜单，当且仅当**同时**满足：
1. 使用频率低（非每次会话都用）；
2. 不是状态强相关（不需要随时看到其启用状态）；
3. 有菜单/快捷键等其他可达路径，或本身是"一次性配置"类操作。

**不得**收纳：直播连接/断开、当前主操作、任何需要实时反映状态的按钮。

## 5. 布局与适配验证（Phase 4 必须实测）

| # | 验证项 | 判定 |
|---|---|---|
| L1 | 最小窗口宽度 | 无按钮被裁剪，无横向滚动 |
| L2 | 1920px 宽 | 布局不松散，分区对齐 |
| L3 | DPI 100/125/150/200% | 图标不模糊、不错位、高度不溢出 |
| L4 | 键盘 Tab 遍历 | 顺序合理，焦点环可见（2px `--ll-accent`） |
| L5 | 窗口缩放中 | 无布局抖动、无闪烁 |
| L6 | 溢出折叠 | 折叠逻辑正确，菜单项可点击且行为一致 |

## 6. 样式隔离要求

**必须**避免样式污染其他界面（Phase 4 独立审计项）：

- 新增 QSS 必须**限定作用域**（用 `objectName` 选择器或独立样式表挂载到工具栏控件），**不得**写入全局 `QApplication.setStyleSheet()` 影响对话框、设置窗口等。
- 不得覆盖 `gui/theme.py` 中既有的全局规则而不做影响面评估。

> **FACT**：项目已有 `gui/theme.py`（31 KB）主题系统。**UNKNOWN**：其结构、作用域与是否全局生效。→ Phase 2 审计后决定"扩展"还是"并存"。
