# WATERMARK_SPEC — 未激活动态水印规格

> **阶段**：Phase 1（设计）/ 实施于 Phase 5
> **依据**：`design-system/livelens/MASTER.md`、`design-system/livelens/pages/preview-watermark.md`
> **证据标签**：FACT / INFERENCE / UNKNOWN

---

## 1. 目标

在直播预览框内部显示**一个且仅一个** `LiveLens` 文字水印，具有 DVD 屏保式碰撞反弹运动，**仅当许可系统确认当前未激活时**显示。

**硬约束**：只存在于 UI 显示层，**不得**对原始直播帧、解码帧、识别输入帧或帧队列做任何修改。

---

## 2. 授权状态来源

### 2.1 原则

- 授权状态**必须**来自现有许可系统的**权威数据源**。
- 水印组件是**纯消费者**：只读取状态，**不**参与验证、**不**写入、**不**缓存判断逻辑。
- **不得**把业务许可逻辑写进绘制代码。

### 2.2 状态语义

| 状态 | 水印行为 |
|---|---|
| 未激活 | 显示 + 动画运行 |
| 已激活 | 隐藏 + 定时器**停止** |
| **未确认 / 未知** | **不得假定为已激活** —— 按"未激活"处理并显示水印（安全侧） |

> **INFERENCE**：把"未知"归到"显示水印"是保守选择。理由：水印是**提示性**标识，误显示只是视觉冗余；误隐藏则失去提示意义。
> **⚠️ 但这是待确认项**：任务书 §5.1 要求"不得根据是否联网、是否连接直播或其他无关条件推断激活状态"。若现有许可系统对"未确认"有**既定语义**（例如已有 `LicenseStatus.UNKNOWN` 分支），**必须遵循现有语义**，不得自行发明规则。→ 见 §2.3。

### 2.3 ⚠️ 待 Phase 2 确认（UNKNOWN）

| # | 问题 | 影响 |
|---|---|---|
| U1 | 许可状态的权威来源是哪个模块/类/属性？ | 决定水印组件的依赖注入方式 |
| U2 | 状态是**可观察的**（信号/回调）还是需要**轮询**？ | 决定"状态变化及时反映"的实现方式 |
| U3 | 现有代码如何表达"未确认/验证失败/离线"？ | 决定 §2.2 的"未知"分支 |
| U4 | 是否已有 UI 元素依赖许可状态（如过期对话框）？ | 复用其既有订阅模式，保持一致 |

**处置**：Phase 2 审计 `gui/activation_dialog.py`、`gui/expired_dialog.py`、`utils/offline_activation.py`（若可读）及许可相关模块后，在本文件补充"实际来源"章节。**在 U1–U4 明确之前，Phase 5 不得开始编码。**

## 3. 运动算法

### 3.1 坐标与符号

| 符号 | 含义 |
|---|---|
| `W`, `H` | 预览区域（覆盖层）宽度、高度 |
| `w`, `h` | 水印实际宽度、高度（含内边距） |
| `x`, `y` | 水印**左上角**坐标 |
| `vx`, `vy` | 水平、垂直速度（px / 每 tick） |

### 3.2 合法范围

```
0 <= x <= W - w
0 <= y <= H - h
```

**必须**用**矩形与合法范围**比较，**不得**只判断中心点。

### 3.3 更新与碰撞（每 tick）

```python
# 1) 先积分
x += vx
y += vy

# 2) 再逐轴修正 + 反转（顺序无关，但两轴必须独立处理）
if x < 0:
    x = 0
    vx = abs(vx)          # 向右
elif x > W - w:
    x = W - w
    vx = -abs(vx)         # 向左

if y < 0:
    y = 0
    vy = abs(vy)          # 向下
elif y > H - h:
    y = H - h
    vy = -abs(vy)         # 向上
```

**要点**：

1. **位置修正是必须的**，不能只反转速度——否则水印会在边缘外停留或抖动。
2. **角落碰撞**：`x` 与 `y` 两个 `if` 块**相互独立**，因此角落处两个轴向速度**同时反转**，满足任务书要求。
3. 用 `abs()` 强制方向，避免因连续两次越界导致速度符号错误（抖动/卡死）。

### 3.4 退化情况（极小预览区）

| 情况 | 安全行为 |
|---|---|
| `W - w <= 0`（水印比预览区宽） | `x = 0`；**不更新 `vx`**（避免抖动）；水印保持左对齐 |
| `H - h <= 0` | `y = 0`；**不更新 `vy`** |
| `W <= 0` 或 `H <= 0`（预览区未布局） | 覆盖层隐藏；**不启动定时器** |
| `w <= 0` 或 `h <= 0`（水印未测量） | 同上，等 `sizeHint` 有效后再启动 |

> **理由（INFERENCE）**：当合法范围为负时，"反弹"在数学上无意义，任何 `x += vx` 都会立刻越界并被钳到 0，造成每 tick 抖动。因此必须**冻结该轴速度**而非反复钳位。

### 3.5 边界重算触发条件

以下任一发生时，**必须**重算合法范围并钳位当前 `(x, y)`：

- 窗口缩放（`resizeEvent`）
- 预览区尺寸变化
- DPI / 屏幕缩放变化（`screenChanged` / `devicePixelRatio` 变化）
- 水印尺寸变化（字体、文字、内边距变化后 `sizeHint` 改变）

钳位后**不得**立即反转速度（那是"位置修正"而非"碰撞"），仅保证不越界。

### 3.6 定时器与刷新频率

| 项 | 规范 |
|---|---|
| 类型 | `QTimer`，**独立于**视频帧刷新 |
| 周期 | **待 Phase 5 实测确定**，起点 16ms（≈60fps 上限） |
| 与视频帧率关系 | **无绑定**。不得用视频帧信号驱动水印 |
| 隐藏状态 | **必须停止定时器**，不得空转 |
| 退出 | `closeEvent` / 析构时**必须停止并断开**定时器 |

> **来源**：Skill `--domain ux` → *Excessive Motion (High)*："Animate 1–2 key elements per view maximum"；*Reduced Motion (High)*。
> **性能预算**：Skill 对 `Liquid Glass` 标注 `cost:moderate | drivers:animation,blur`。水印是常驻动画，**必须在 Phase 7 单独测量其开启/关闭时的 CPU 差异**。

## 4. 组件边界（实现方案）

### 4.1 推荐结构

| 方案 | 说明 | 评价 |
|---|---|---|
| **A. 独立透明覆盖 QWidget** | 作为预览容器的兄弟控件，`raise_()` 置顶，`WA_TransparentForMouseEvents` | ✅ **首选** |
| B. 视频控件内自绘 | 在视频控件的 `paintEvent` 里叠加绘制 | ❌ 拒绝：把水印写进视频绘制路径，违反隔离原则 |
| C. `QGraphicsView` 场景叠加 | 用图形场景的 item 叠加 | ⚠️ 仅在项目**已经**使用 QGraphicsView 显示视频时考虑 |

**FACT**：项目存在 `gui/video_widget.py`（7.7 KB）。**UNKNOWN**：其是否基于 `QGraphicsView`、`QLabel`、还是自绘 `QWidget`。→ Phase 2 确认后定稿方案。

### 4.2 必须满足的隔离性质

1. 视频显示代码**零改动**（除必要的父容器调整以容纳覆盖层）。
2. 水印绘制**不读取**任何视频帧数据。
3. 水印**不进入** OCR / ROI 输入链路。
4. 水印模块**不导入**许可验证实现，只依赖一个状态值（或状态信号）。

## 5. 测试矩阵（Phase 5 必须全覆盖）

| # | 用例 | 判定标准 |
|---|---|---|
| T1 | 只有一个实例 | 遍历控件树，水印实例计数 == 1 |
| T2 | 水平碰撞 | `vx` 在左右边界处符号反转；`0 <= x <= W-w` 恒成立 |
| T3 | 垂直碰撞 | 同上，垂直轴 |
| T4 | **角落碰撞** | 到达角落时 `vx`、`vy` **同时**反转 |
| T5 | 不越界（长跑） | 连续 N tick 后 `x`、`y` 始终在合法范围 |
| T6 | 窗口缩放 | 缩放后水印仍在范围内，无越界 |
| T7 | 极小预览区 | `W < w` 时不抖动、不异常、不越界 |
| T8 | 未激活显示 | 状态=未激活 → 可见 + 定时器 active |
| T9 | 已激活隐藏 | 状态=已激活 → 不可见 + 定时器 **inactive** |
| T10 | 状态切换 | 激活↔未激活双向切换正确，无残留定时器 |
| T11 | 直播连接前 | 未连接时在空白背景上运动 |
| T12 | 直播连接后 | 连接后仍为独立层，视频层未被修改 |
| T13 | **不改原始帧** | 对同一帧缓冲区做哈希，水印运行前后**哈希不变** |
| T14 | **不改识别输入/ROI** | ROI 坐标、识别结果在水印运行前后一致 |
| T15 | 定时器生命周期 | 程序退出后无 `QTimer` 存活、无 "QTimer destroyed while running" 警告 |

> T13/T14 是**任务书的核心红线**，必须用**可复现的自动化断言**验证，不能只做人工观察。

## 6. 性能约束

| 约束 | 说明 |
|---|---|
| 不得阻塞 UI 线程 | 运动计算是 O(1) 纯算术，无 I/O |
| 不得与帧率绑定 | 独立定时器 |
| 隐藏时零开销 | 定时器必须停止 |
| 不得在视频帧路径引入处理 | 无模糊/折射/额外拷贝 |
| 绘制成本 | 每 tick 只重绘**水印矩形区域**（`update(rect)`），不整层重绘 |
